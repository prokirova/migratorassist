# Протокол замеров: чанкинг и качество поиска (практика 2)


## Исходные данные

> Три текстовых файла в `data/raw/`, страниц у них нет (в метаданных `page = 0`):
 
- `release-notes.md` — история релизов FastAPI (Markdown, англ.)
- `migration-guide.txt` — руководство по миграции с Pydantic V1 на V2 (TXT, англ.)
- `pypi-xmlrpc-api.txt` — описание XML-RPC API PyPI (TXT, англ.)
Размеры файлов: 752 Кб. Вопросы проверочного набора написаны по-русски, документы английские.

## Словарь рубрик

>Рубрика определяется правилами. Сначала проверяется имя файла, затем ключевые слова в чанке; побеждает 
> рубрика с наибольшим числом совпадений. Рубрика по умолчанию — `other`.

| Рубрика     | По какому правилу присваивается                                                                                                        |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `pypi_api`  | имя файла содержит `pypi` или `xmlrpc`                                                                                                 |
| `migration` | имя файла содержит `migration`                                                                                                         |
| `breaking`  | ключевые слова: breaking change, deprecated, removed, drop support, security, vulnerability, cve-, csrf, redos                         |
| `changes`   | ключевые слова: feature, add support, fix bug/issue/handling, regression, bump, upgrade, refactor, workflow, github action, pre-commit |
| `docs`      | ключевые слова: documentation, typo, tutorial, update docs, translation                                                                |
| `other`     | по умолчанию, если ни одно правило не сработало                                                                                        |

Пустых значений `category` нет. Фильтр `where={"category": "pypi_api"}` возвращает только чанки этой рубрики.

## Замеры

Значение k = 5 (`TOP_K` в `config.py`). В каждом прогоне дополнительно снимался hit-rate@1.

| № | Очистка | CHUNK_SIZE | CHUNK_OVERLAP | Чанков в индексе | hit-rate@5      | hit-rate@1     |
|---|---------|------------|---------------|------------------|-----------------|----------------|
| 1 | v1      | 512        | 64            | 1656             | 59 % (10 из 17) | 53 % (9 из 17) |
| 2 | v1      | 256        | 64            | 3862             | 53 % (9 из 17)  | не снят        |
| 3 | v1      | 512        | 128           | 1932             | 47 % (8 из 17)  | не снят        |
| 4 | v2      | 512        | 64            | 1104             | 59 % (10 из 17) | 53 % (9 из 17) |

**Выбранные значения и основание.**

> Принято CHUNK_SIZE = 512, CHUNK_OVERLAP = 64 (заданы в `config.py`). 
> По hit-rate@5 нарезка 512/64 лучше вариантов 256/64 и 512/128 (59 % против 53 % и 47 %).
> На очистке v2 результат не изменился. Разница в 1–2 вопроса невелика, поэтому выбор дополнительно опирается 
> на вторичный показатель — число чанков (512/64 даёт самый компактный индекс).

## Уточнение метрики из технического задания

> На практике 1 была объявлена метрика hit-rate@5 ≥ 60 % (набор из 5 вопросов).
> При первом замере на итоговом наборе (17 вопросов) получено 59 %.
> Число оставлено как цель 60 %.
> Причина небольшого недотягивания — систематическое вытеснение двух маленьких документов (`migration-guide.txt` и `pypi-xmlrpc-api.txt`) большим `release-notes.md`.
> Дальнейшие шаги: усиление фильтрации по рубрикам и добавление префиксов `query:` / `passage:` для модели E5.
